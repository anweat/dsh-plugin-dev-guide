## 一、工作背景

为贯彻落实国网营销部关于印发 2026 年"人工智能+营销专业"工作安排的通知要求，探索开展网上国网智能交互能力建设。网上国网余额查询能力通过 API 及在支付宝光华平台配置接口转化成 MCP 服务形式对 AI 版支付宝开放，整合支付宝已有生活缴费能力，实现用户余额查询需求。

## 二、技术方案

### 2.1 技术思路及实现方式

#### 2.1.1 接入方式

**（1）用户鉴权**

用户中心依据客户端获取阿宝的一次性授权码调用阿宝服务端获取 openId，通过 openId 换取阿宝手机号之后，校验是否已完成国网内部授权，已完成则进行一键登录逻辑完成登录，未授权则根据手机号判断是否已注册，未注册则进行一键注册，完成后建立注册信息与三方 openId 授权关系最终完成一键登录逻辑完成登录流程。阿宝用户鉴权链路与目前支付宝鉴权一致。

**（2）查询余额**

网上国网根据 AI 支付宝内嵌服务卡片开发规范开发余额卡片（H5 页面），通过网上国网能力开放平台调用网上国网后端查询业务数据，卡片开发完成后，发版静态页面至外网环境，由支付宝"阿宝"智能体通过 API 接口调用网上国网余额卡片显示网上国网余额数据。AI 支付宝调用前端卡片时，需要在支付宝光华平台进行 MCP 服务托管模式配置，配置好后，支付宝侧自动将 API 接口转化为 SPI 接口并带有 MCP 服务。

**登录国网账号相关流程说明**

第一：前端在阿宝聊天界面通过调用 JSAPI ap.getAuthCode 接口唤起半屏授权浮层；第二：用户确认授权后，API 接口返回 auth_code，前端通过能力开放平台提供的接口将 auth_code 值传递至用户中心，通过用户中心和支付宝服务端交互获取用户信息后，用户中心处理完毕国网内部登录逻辑，返回前端基本用户信息。第三：在用户登录/注册国网账号成功后，前端调用查询余额的业务数据接口将数据呈现在前端卡片上。

**（3）查询余额的业务数据接口**

提供首页余额查询接口，详情见附件 2，需支付宝阿宝侧在调用接口时，在渠道标识字段中传输支付宝阿宝侧固定的渠道标识。

### 2.2 数据规划

数据流转：与网上国网现有数据架构保持一致。数据存储：与网上国网现有数据架构保持一致。数据增长估算：支付宝智能体通过授权方式给网上国网带来新增用户，上线前期会带来大量新增用户。

### 2.3 实施方案

2026 年 7 月完成产品设计确认；2026 年 8 月完成开发、测试；2026 年 9 月底完成正式环境配置及上线。

### 2.4 上线目标

使用群体：使用支付宝"阿宝"查询余额的用户。

### 2.5 资源评估

静态资源 H5 卡片部署，初步评估无需扩容资源。

### 2.6 风险评估

无暴露风险，支付宝智能体只与前端卡片做交互，不调用国网数据。
